# 槽位绑定命令：核查结果与必要资料

## 当前结论

尚未取得目标服“芒果小镇主菜单 / 仓库菜单 / 系统商店”的实际绑定配置，不能确定其槽位背后的指令，也不能确认它们一定有普通玩家可手输的等价指令。本次没有猜测执行命令，没有探测服务器隐藏接口，没有直接重放临时窗口/槽位。

## 已检查的证据

- 本地 MC 26.2 的 ServerboundContainerClickPacket，用 Java 25 的 javap 只读核查。数据为 containerId、stateId、slotNum、buttonNum、containerInput、changedSlots、carriedItem；没有菜单绑定命令字符串字段。窗口 ID 是本次打开界面的关联标识，不是稳定功能命令。
- 当前项目中与工作台/商店/市场有关的源码与文档：除测试示例和边界说明，未发现来自该服真实配置的映射。测试里的 workbench 不属于实服取证，不能使用它冒充发现的指令。
- 对该服名称/域名/功能的公开检索未获得可核实的槽位映射；网站访问也没有提供本轮可用的实际菜单配置。未访问需权限的配置或后台。
- 2026-10-11 通过 GitHub 官方仓库 API 只读查看 HelpChat/DeluxeMenus：ActionType.java 定义玩家命令、控制台命令和打开菜单等不同动作；ClickActionTask.java 由服务端调用 player.performCommand、Bukkit.dispatchCommand 或 menuToOpen.openMenu。绑定关系因此可能只存在于服务端。这里只是已验证的插件实现案例，不宣称目标服使用它。

## 能可靠确定的途径

1. 服务端所有者提供相关菜单配置和插件类型/版本。按菜单、页面、槽位和点击类型读取实际动作，并同时核查条件、占位符、权限与冷却。动态菜单或数据库生成菜单应提供实际生成逻辑，不能只用物品显示名。
2. 管理员提供该槽位实际执行动作的调试输出，或确认对外公开的命令入口。只认可带来源的对应关系，不把通用插件默认命令当作此服真实配置。
3. 若服务器在帮助或已有可见补全中公开入口，用户按规则手动确认能打开目标功能。这能确认有可手输入口，但单凭功能效果相同仍不能证明它就是该槽位内部绑定的命令。
4. 若服务器明确把完整指令发给客户端，或客户端点击时真的发送指令包，新版监测会记录它；没有文字命令包时不会生成假的指令结果。

以 DeluxeMenus 配置为例，需要检查对应 item 的 slot/slots、left_click_commands/right_click_commands 等实际字段；open_command 通常是打开整份菜单的入口，并不等于每个槽位的绑定。控制台命令不等于普通玩家可手输命令，直接打开菜单的内部动作也不必存在同名文字入口。其他插件要用其自身配置格式核查。
