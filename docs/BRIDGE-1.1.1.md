# 桥接 Mod 1.1.1

## 本次交付

- 配合已发布的芒果端辅助 2.4.19，提供出站指令、菜单槽位/按钮、物品使用和服务器打开界面的被动监测。
- 保留原聊天桥接、原配对协议、红包动作和可选钓鱼 Mod 适配；钓鱼模块仍为单独的 Mod，本 JAR 不内置它，也不要求重复安装。
- 提取能力握手为可离线测试的 BridgeHandshake，固定上报 outboundMonitor=true；仅桌面明确返回布尔 true 时开始监测。旧软件不提供能力时，继续原聊天功能，不向旧软件发送观察帧。
- 游戏启动日志包含实际桥接版本，配对日志包含监测协商结果，不记录令牌。不会用版本号替代真实能力协商。
- 桌面便携 EXE 未修改，仍使用 2.4.19；只更新游戏中的桥接 Mod。

## 替换步骤

1. 退出 Minecraft，确认使用原来配对的 MC 26.2 / Fabric 实例。
2. 将该实例 mods 中旧的 mc-noclient-bridge JAR 移到备份位置，放入 dist-2.4.19/mc-noclient-bridge-1.1.1+26.2.jar。不要同时保留两份相同 Mod ID 的桥接 JAR，不改其他 Mod。
3. 保留 config/mc-noclient-bridge.json 配对文件，不重新导出、不覆盖令牌。
4. 使用现有 2.4.19 软件启动游戏桥接，按原方式启动游戏并进服。正确加载新 Mod 并协商后，应出现“游戏出站指令与菜单监测已启用”，不再提示当前 Mod 未提供监测。
5. 在游戏中打开右键菜单并点击一次目标功能，查看软件“运行日志”的“连接与协议”分类。游戏指令显示实际命令；只有槽位点击和界面记录时，不能可靠推导服务端内部命令。

适配限制：Minecraft 26.2、Fabric Loader 0.19.3+、Java 25、对应 Fabric API。不是 Forge/NeoForge 或其他 MC 版本通用包。项目构建仅只读本地游戏库，没有自动执行以上安装步骤。

## 验证与边界

- 构建脚本改为直接针对输出 JAR 运行 ActionRegistryTest、MonitorSafetyTest、BridgeHandshakeTest、MixinTargetTest，均通过。
- 包内验证身份/版本/目标、客户端入口、三组 Mixin、八处非取消型回调的本地 26.2 描述符、能力握手调用和钓鱼适配调用，均通过。此为静态字节码和离线测试，不是游戏运行时 Mixin 验证。
- 软件端桥接 22、出站监测 14、人数领取 33 项回归全部通过；2.4.19 EXE 哈希不变。
- 监测被动记日志，不阻塞或改写游戏操作，不新增重放指令。登录等常见私密参数双端脱敏，普通参数仍可能含自定义插件敏感信息；限流/字段长度/原日志内存上限保持。详见 OUTBOUND_MONITOR.md。
- 未启动真实游戏、未修改游戏目录/真实配置/配对、未连接服务器。用户替换后仍需验证整合包加载与实际菜单监测。
