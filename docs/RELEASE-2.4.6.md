# 2.4.6 在线记录与聊天接收取证

2026-10-09，MC 26.2 / 协议 776。

用户最新要求：进出服通知默认隐藏但保存，能按玩家查询在线时间；明确为什么玩家聊天仍缺失。

保留此前约束：不发实服测试聊天，不在短时间重复登录，不为了补样本干扰用户连接。本轮没有再次连接目标服务器，没有实服聊天或命令，未关闭用户旧程序，未修改真实账号/配置。

## 在线记录

- `src/presence.js` + `app/main.js`：主进程识别完整 `[+]` / `[-]` 通知，写入固定 userData 的 `presence.jsonl`，包括原文、时间、服务器、观察会话。记录不依赖聊天显示；隐藏或清空聊天不删除历史。写入失败有日志和查询警告，内存待写事件下次追加时重试。
- 新增"在线记录"页签，选择服务器、输入玩家名可查询本地历史。按服务器/端口隔离，名字不区分大小写。
- 完整连续上下线区间才计累计时长；缺开始、缺结束、监控断线或崩溃都显示未知，不跨断线空白拼接。
- 显示最近 200 个区间，累计覆盖全部记录；软件未连接期间与旧版没保存的历史不能恢复。
- 设置新增 `display.hidePresence`，默认 true；聊天"进出服记录"分类可临时查看收到的通知。
- 查询和运行日志页收起资源监控，为内容让出高度，不修改用户的监控设置。

## 协议修正

**确认修正**：同步坐标字段顺序和传送 ID 原实现错误，现按 26.2 固定定义正确读取，含三个速度分量与相对坐标/旋转；切回配置阶段补上 `0x10` 回执。

## 不能声称已修复目标服玩家聊天

- 旧实服报告只有 5 条 system 消息，没有 player_chat 原始包计数。本地 say/tellraw 回归不是玩家发言回归；签名玩家包目前仍是离线构造夹具。此前验收缺少真实玩家聊天证据。
- 坐标错误虽已确认，未证明是该服务器聊天缺失的直接原因。**不要把"缺聊天公钥""服务器没发"或"未确认传送"当作已确认根因。**
- `MCClient.getChatDiagnostics()` 记录四条聊天包路径接收/正文输出/失败计数、正文回退、Play ID 频次和坐标回执。运行日志实时显示，断开后保存 `chat-diagnostics-last.json`，不包含聊天原文或凭据。
- 0 个 player 包只表示没进入标准玩家路径，插件重写后的玩家发言仍可能走 system/profileless。下次用户正常使用新版时利用这些计数取证，**不要为了采样再执行实服脚本**。
- `docs/CHAT_DIAGNOSIS.md` 保存了证据、不能推断的结论和在线时长口径。
