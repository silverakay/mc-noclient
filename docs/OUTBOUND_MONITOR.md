## 能看到什么

- 当前多人游戏主线程提交到当前连接的普通、带签名聊天指令包。仅提取指令字符串，不读取签名、盐值或其他认证字段。
- 容器槽位点击：窗口 ID、槽位、按钮、操作类型、当前界面标题及点击前的物品显示名。点击前取样只有与实际发送包匹配且未过期才使用；没有匹配就明确记录没有取到物品。
- 容器按钮点击、主手/副手使用物品、对方块使用物品。
- 服务器打开容器界面：真实界面标题、窗口 ID、菜单类型。
- 不抓取移动、普通聊天、登录协议、背包全部内容或自定义 payload 原始数据；其他 Mod 在后台线程直接发送的包不在本版监测范围内。

观察只写桌面软件的“运行日志”，分类为“连接与协议”；不生成聊天消息，不登记自动执行动作，不自动重放。
日志沿用每页最多 800 条的内存上限，不跨软件重启保存。

## 如何判断菜单功能是否有指令

启动桥接、游戏进服后，在游戏内打开菜单并点击一次目标功能，再看相应时间的运行日志。
只有出现“[游戏指令] … 提交出站：/…”时，才表示观察到客户端实际提交了该条指令。正常长度且未脱敏的指令保留完整参数，可以手动填入现有输入框。

若只出现“[菜单监测] … 槽位 …”和“[服务器界面] … 工作台”，客户端发出的可能只有槽位点击包；服务端插件收到后在内部打开界面，本机没有收到它内部的命令名称。此时不能从槽位号或界面名可靠推导出聊天指令，更不能自动生成 /workbench 等猜测。
界面日志与前面的操作只是按时间排列，不宣称存在经过服务端确认的因果映射。

即使看到真实指令，也不证明服务器已执行或允许日后重复使用；临时动作 ID、权限、冷却和菜单上下文可能影响结果。
“提交出站”指当前连接的 send 三参数方法返回，不是服务端收件回执；其他 Mod 的拦截或改写仍可能影响最终发送。

## 隐私与性能

- Mod 在本地传输前隐藏常见 login / l / register / reg / changepassword / password / auth / otp / email 等指令的全部参数，命名空间形式也处理；桌面接收端再次脱敏。
- 自定义插件私密指令无法仅凭名称全识别。非上述指令的普通参数会被记录，不要把此功能当作对所有自定义凭据的保密保证。
- 指令超过 2047 字符时只留命令名并注明“过长参数未记录”，不展示可误复制的截断参数。
- 标题和物品名最多 256 字符；控制字符清洗。没有原始 payload、完整背包或配对令牌记录。
- Mod 每秒最多 20 条普通观察；出站桥接队列为聊天、状态和执行回执预留 32 个位置。繁忙时丢弃观察记录并汇总省略数，不取消或阻塞游戏操作。
- 主线程监测异常只关闭本地观察功能，保留原聊天桥接；游戏日志会提示异常类型，不包含包内容。

## 兼容与替换

软件与 Mod 在原协议版本 1 中协商 outboundMonitor 能力，只有双方支持才发送观察帧。
新软件配旧 Mod 保留原聊天桥接但不能监测；新 Mod 配旧软件不会发送旧软件无法识别的观察帧。

用户自行退出游戏后，用 dist-2.4.19/mc-noclient-bridge-1.1.1+26.2.jar 替换同实例 mods 中旧的桥接 JAR，不要同时留两份同 ID 的桥接 Mod。
原 mc-noclient-bridge.json 配对文件继续使用；不要求重新导出配对，不修改游戏验证方式，也不安装到其他实例。
