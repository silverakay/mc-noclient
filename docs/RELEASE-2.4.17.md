# 芒果端辅助 2.4.17

## 红包领取批次修正

- 红包发送者立即进入运行日志，领取明细先暂存；收到发送广播 10 秒后，在运行日志中一次显示人数和全部领取人/金额，不再回放到聊天页。
- 不将示例中的 20 人当作上限；每位领取人按名字不区分大小写去重，保留窗口内实际收集到的明细。
- 定时器延迟不延长收集窗口；同一发送者再次发红包不会提前显示旧批次。广播没有红包 ID 时，新领取按同一发送者最近一批归集，无法可靠区分重叠的同名红包。
- 玩家伪造消息、没有对应发送广播的领取信息不被截留；断线/换服取消待处理批次。

## Nan_Koi 运行日志

- 聊天入口统一检查消息文本；包含 `Nan_Koi` 的消息会额外写入运行日志。
- 新增“Nan_Koi 聊天”日志分类，普通聊天不会被重复写入运行日志。
- 若 `Nan_Koi` 出现在截留的领取消息中，随对应红包批次一同显示在“自动化动作”日志中，不提前泄露领取明细。
- 沿用现有运行日志内存保留方式，不增加跨重启的聊天存档；日志页最多保留 800 个条目，红包多行明细算作一个条目。

## 在线玩家

- “在线记录”页签改为“在线玩家”，只保留当前连接收到的实时玩家名单、延迟和本地筛选。
- 停止追加在线历史事件，也移除历史查询表格和 IPC；旧 `presence.jsonl` 文件保留但不再使用，避免未经确认删除用户数据。
- 玩家名单仍使用内存更新，断线、换服后清空；高人数列表继续复用已有 DOM 节点。

## 菜单与零点命令边界

- 当前桥接协议没有回传游戏内右键菜单点击的具体动作，服务器菜单仍为只读预览，不将菜单动作猜测为可执行命令。
- 每日零点发送逻辑保持现状：不增加高频重试，避免延迟场景下重复发送或触发服务器限制。
