# 2.4.4 自动重连与设置

2026-10-09，MC 26.2 / 协议 776。

用户本轮要求：除主动断开外，网络等外部因素造成掉线要自动重连；添加设置并整合部分现有功能。

**此要求授权开发自动恢复功能，不代表授权本轮反复连接实服测试。** 本轮没有连接目标服务器，未发送实服聊天或命令。

## 改动

- `src/reconnect.js`：成功加入后才启用恢复；默认开启，起始 5 秒，连续失败按 5/10/20/40/60 秒退避，最多 10 次；上限 0 为不限。只记目标 host/port/username/正版模式，不保存令牌。
- 主动断开、停止/取消重连、退出账号、关闭软件取消等待和未完成的异步连接；取消后不会被晚到回调恢复。
- 重连保留实际已连接的目标，不跟随左侧选中项；明确封禁、白名单、凭据失效、版本/公钥拒绝停止，包括中文翻译后的原因。
- 正版恢复走已有静默续期链，临时错误继续重试、授权失效停止，不打开设备码登录；自动重连不重复问候和配置自动命令。
- `src/client.js` / `app/main.js`：登录/配置阶段 45 秒超时，Play 阶段超过 90 秒无任何服务器数据判为网络中断；收到数据会刷新时间，业务发送不会掩盖接收中断。
- 齿轮打开原生设置弹窗：自动重连开关、起始间隔 3–60 秒、重试上限 0–1000、启动自动登录、聊天显示、聊天/日志自动滚动、资源监控显示、数据目录。
- 设置统一保存，取消丢弃草稿，保存失败保留草稿并提示；数字校验、等待保存时禁用、防背景焦点、ESC、最小窗口滚动均检查。
- 首次手动连接失败不自动循环，启动也不自动连接；历史 `lastServer` 不复活。配置读取错误不启用自动恢复，修复保存后不持久化临时错误标记。
- 两个本地 HTTP 认证测试增加 fetch 禁用端口探测/重绑定，修正系统偶然分配 6679 导致 `bad port` 的假失败；没有改生产认证策略。
