# 2.4.12 异地登录自动转桥接

独立登录器被同账号游戏登录挤下线后，现在会直接尝试接管已配对的本地游戏聊天通道，不需要再手动切换模式和点击启动。

## 行为

- 只在当前独立连接收到明确异地登录、重复登录或 `duplicate_login` 的服务端踢出事件时触发。普通关闭/断网、维护和封禁不会自动转桥接，原维护等待规则保留。
- 立即停止独立重连，关闭旧连接，保存游戏桥接模式并启动回环监听。不会第二次登录服务器、刷新微软账号、启动游戏或导出新的配对文件。
- 使用现有 `bridge-pairing.json`，检测窗口为 15 秒，包含本地监听启动耗时。只有令牌认证通过且同一用户名的 Mod 报告游戏已进服才接管；只找到 Java 进程、完成配对或停留主菜单均不算成功。
- 没有配对文件、配对损坏、模式保存失败、端口占用或 15 秒内没有符合条件的游戏时停止。不会自动回到独立登录；已成功切换的桥接模式保留为空闲，可手动启动或切回独立模式。
- 账号不匹配的本地会话会断开，剩余时间内仍可等待正确账号；不延长检测窗口。游戏当前服务器地址由已认证 Mod 报告，不通过服务器别名或 SRV 地址猜测客户端身份。
- 原桥接 Mod 1.0.0+26.2 无需更换。必须先导出配对文件到游戏实例 `config/mc-noclient-bridge.json`，仅安装 Mod 不够；缺失配对不会自动生成或修复。
- 检测期间现有连接面板显示“检测本地游戏 · 最多 15 秒”和“停止检测”，不新增区域或设置。手动停止、退出账号、退出软件、切换模式均取消，迟到的旧连接/状态/计时器不能恢复或停止新会话。
- 接管复用红包去重和欢迎每日限额，不重复入服问候/预设指令，不重置计数或补发零点命令。成功后按原桥接规则等待本地通道恢复，不独立重连；本次限时检测只约束初始自动交接，手动启动桥接仍持续等待。
- 与“网络异常自动重连”开关独立：关闭网络重连不阻止一次本地交接，交接本身从不创建第二条服务器连接。

## 边界

明确异地登录也可能是别处真实登录，不能假定一定有本地游戏；未检测到就停止。服务端给出的原因不明确时仍按原断线策略处理，不根据网络故障猜测游戏接管。
本次没有操作用户游戏/启动器/运行中的软件、改真实配置、安装 Mod、连接目标服务器或发送实服测试命令。离线模拟通过不等于实机加载、服务端收到或红包到账通过。
界面保留原视觉系统，机械检测的旧对比度、字号、发光等警告不在这次小修改中整体重设计。

备份：`backups/2.4.11-before-auto-bridge-20261010-122604`，含改动前源码与两个旧 EXE。新发布使用 `dist-2.4.12`，不覆盖 2.4.11。
