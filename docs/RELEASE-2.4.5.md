# 2.4.5 红包自动点击与消息分类

2026-10-09，MC 26.2 / 协议 776。

用户本轮要求：可连接实服测试，但不在聊天栏发送测试信息，不在短时间内重复多次连接；自然收到 `[红包]` 消息时自动点击末尾领取动作并记录日志；聊天与运行日志去除大量重复内容并分类。

## 改动

- `src/red_packet.js`：识别服务器红包前缀和末尾领取按钮，自动执行其原始 `run_command`；不是服务器消息、不是领取、无动作、URL/复制、普通聊天不执行。
- `suggest_command` 只通知界面填空输入框，不猜口令、不自动发送，不覆盖已有输入。不能承诺所有口令红包无人干预领取。
- 设置 `automation.autoClaimRedPackets` 默认 true，可关闭，旧配置升级补齐。去重 120 秒、上限 1024 条，最多每分钟 10 个入口；断线清待确认计时，但保留短期去重。
- 动作注册在主进程；自动发送后同命令的按钮失效，避免手动再发。日志记录"已发送，待确认"，只有自然收到本人领取反馈才记确认；30 秒未确认不能当作到账。
- `app/main.js` 不再将收到的聊天复制到运行日志；显示设置不影响主进程红包识别。运行日志只留下连接/登录/错误/应用操作和领取审计。
- renderer 添加聊天类别（玩家/服务器通知/红包/快捷栏）和日志类别（连接/账号/领取/错误/应用），手动发送的命令不在聊天页再次回显。
- `tools/live_receive_probe.js`：一次连接、最长 120 秒自然观察，禁用测试聊天/命令/问候/重连，只有自然服务器领取动作可执行，15 分钟冷却文件 `dist\live-receive-cooldown.json` 不得绕过或删除来重试。
