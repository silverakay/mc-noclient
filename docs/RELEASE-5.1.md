# 芒果端辅助 V5.1

更新日期：2026-10-22（Asia/Shanghai）。内部版本：5.1.0。

## 更新

- 合并独立连接的菜单普通左键、右键点击与重复提交、旧窗口失效、光标物品保护。详见 `MENU_CLICK.md`。
- 可见版本改为 V5.1；以后每次交付依次 V5.2、V5.3，内部版本为 5.2.0、5.3.0，不复用旧版本号。
- 正式打包要求代码签名；没有签名配置时停止发布，不再把未签名包作为已解决发布者验证问题的正式交付。
- 配置和账号目录保持不变，桥接 Mod 仍为 1.2.0。

## 发布者拦截的实际原因

Windows Code Integrity 事件 3077、3033 明确记录上次 EXE 不满足签名级别要求；EXE 为 `NotSigned`，没有下载区域标记。
`VerifiedAndReputablePolicyState=1`，系统开启智能应用控制。这不是修改显示名称、版本号或删除下载标记能够解决的问题。

微软说明智能应用控制只认可受信任提供方签发的代码签名证书：
https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control

本机只发现其他项目名称的自签名开发证书，没有发现本项目可用的受信任发布签名身份。本次没有使用该证书、修改信任根或关闭应用控制。

## 当前交付状态

源码已更新至 V5.1，签名身份尚未配置；**发布者拦截尚未修复，不交付可运行承诺**。
需要用户提供或指定获授权的受信任代码签名证书/签名服务后，再签名、生成 V5.1 包并进行启动验收。私钥及密码不要发到聊天或写入仓库。

可通过 electron-builder 的本地受保护环境配置签名凭据（如 `WIN_CSC_LINK`、`WIN_CSC_KEY_PASSWORD`），或使用正式签名服务配置。
设置中不得关闭 `forceCodeSigning` 来冒充修复；即使签名完成，也应验证 Authenticode 状态和实际系统策略是否允许启动。
