# 2.4.3 中文聊天与手动点击

2026-10-09，MC 26.2 / 协议 776。

用户已提供 2.4.2 的实服日志，里面确有自然收到的红包、签到、死亡、进度等内容，此前"完全接收不到消息"的问题已改善。本轮请求是修正英文翻译键，并使红包等服务器聊天组件可以点击。

## 改动

- `src/chat_component.js`：中文翻译、`%s` / `%1$s` / `%%`、递归组件、颜色、格式、悬停文本；兼容 `click_event` 和旧 `clickEvent`。
- `src/lang/zh_cn.json`：26.2 官方简体中文语言表，8562 条；SHA-1 已校验。运行时离线读取，不下载资源。
- `tools/update_chat_language.js` 与 `src/lang/SOURCE.md`：固定版本、资源来源和可复现下载校验。
- `src/client.js` / `src/nbt.js`：系统消息、无档案消息、快捷栏和玩家聊天都保留富文本；玩家聊天优先显示服务端修饰正文；配置阶段提前报告 `zh_cn`。
- `src/chat_actions.js`：由主进程保存服务器原始动作，仅接受动作 ID；限制容量、断开/换服失效、执行指令单次消费。
- `app/main.js` / `app/preload.js` / renderer：点击指令只手动触发；填入指令只填输入框；链接需确认且仅 http/https；复制动作走剪贴板；旧连接按钮禁用。
- 手动发送现在等待 IPC 成功后回显，失败保留输入内容；不再把未发送消息显示成成功。

## 限制与解释

- 插件的红包广播可以通过 `system_chat` 传来，"系统消息"不代表没有玩家相关内容，不应过滤掉。
- 内置翻译键如 `death.attack.mob`、实体名称、进度标题会显示中文；插件直接发送的英文原文不猜测翻译。
- `run_command` 发送服务器提供的指令；`suggest_command` 仅填入输入框，用户仍需填口令并手动发送。
- 未实现自动抢红包，未硬编码红包插件命令，未猜测口令。只有带服务器点击动作的新消息可点击，复制的纯文本没有动作，不能恢复。
- 收到消息不会执行动作。离线测试中的指令仅进入 mock 接收器，不连接、不发送到实服。
- 真实红包领取是否成功、是否过期、名额和插件兼容性未实服验证。
