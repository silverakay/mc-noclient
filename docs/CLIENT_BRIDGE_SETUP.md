# 游戏在线时保留自动领取

当前软件源码：V6.4（6.4.0），桥接 Mod 1.7.0。**仅适配 Minecraft 26.2、Fabric Loader 0.19.3 或更高、Java 25、对应 Fabric API**。保留双开独立端口与账号设置；新增桥接下线成功后独立连接接管，可选普通游戏下线后也接管。同账号被游戏挤下线后的自动桥接检测仍最多 30 秒。V6.3 的发现配对可沿用，更老固定端口配对需重新导出以支持双开，原令牌保留。
本次开发使用本地实例的 26.2、Fabric API 0.157.0+26.2 和 Java 25.0.1 编译。

## 正版服可以使用

桥接不需要离线登录，也不会绕过正版验证。PCL 启动的游戏按原方式完成正版验证；软件复用游戏已经建立的连接收发消息，不再以同账号登录服务器。
软件账号栏未登录不妨碍桥接；桥接模式下跳过软件的启动自动账号续期。
游戏关闭或断线后，桥接不能继续领取。仅在设置允许且明确确认游戏已下线时，软件才会使用同一账号独立连接接管；只有桥接通道断开而无明确游戏离线证据时，不自行登录。

## 安装与配对

以下是用户确认后执行的步骤，本轮没有自动安装、复制配对文件到游戏目录或启动游戏。

1. 保留旧程序和备份。退出旧软件后使用 V6.4 未签名便携版或源码；可以同时启动两个新版窗口，不混用旧窗口。未签名不等于发布者验证通过。
2. 在 PCL 中确认目标实例。游戏退出后，备份移出旧桥接 JAR，再将 `dist-6.4.0-unsigned/mc-noclient-bridge-1.7.0+26.2.jar` 放入各实例的 `mods` 目录，不两份同 ID 并存。独立连接无需桥接 Mod。
3. 每个游戏实例都必须有自己的 `config/mc-noclient-bridge.json`。软件切换到“游戏桥接”后点“导出配对”，保存到对应实例的 `config` 目录。V6.3 导出会加入本机监听发现路径，原令牌不变。同一软件数据目录的两个窗口共用配对身份，但各自使用独立端口，无需手动编辑端口。
4. 点软件“启动桥接”，再按原方式通过 PCL 正版登录游戏和服务器。也可以游戏先在线，再启动软件桥接；Mod 每 5 秒重试的仅是本机通道。
5. 软件应从“等待游戏”变为“已进入游戏”，验证栏显示“游戏连接”。红包自动领取沿用设置中的开关；查看“自动化动作”日志区分指令处理与服务器领取确认。
6. 需要上线下线功能时，在当前服务器的“设置 → 桥接下线”选择或填写 ID 并启用。所选玩家已经在线时，保存后即触发。普通“断开桥接”仍只断开辅助通道。
7. “设置 → 连接 → 游戏下线后独立接管”默认仅对桥接下线成功生效；可关闭，或改为普通游戏下线后也接管。需提前在辅助保存同一游戏账号的正版凭据。普通模式需要 Mod 1.7.0 的明确离线报告；游戏关闭或崩溃导致桥接直接丢失时不猜测接管。

本次只读定位的实际实例目录：

```text
I:\minecraft-run\.minecraft\versions\26.2-Fabric 0.19.3
```

配对文件含随机令牌，是本地命令通道的凭据，不要公开、上传或发到聊天。软件原始配对文件存放在它的数据目录 `bridge-pairing.json`；端口和令牌不会写入运行日志。

## 双开与 Voxy

两个游戏必须使用不同账号；每个辅助窗口同时接管一个游戏。未绑定窗口按可用顺序首次配对，配对后按游戏身份固定，不自动切换到另一个账号。自动交接只匹配原账号。暂停或停止一个窗口不影响另一个窗口的监听。

安装了 Voxy 时，不要让两个游戏进程共用同一游戏目录或 Voxy 数据库。2026-10-25 12:51:28 的本机崩溃报告明确是 Voxy/RocksDB 的 `storage/LOCK` 冲突，与桥接端口错误独立。请在 PCL 创建两个实例并启用游戏目录隔离，确认 `--gameDir` 路径不同；或在专用第二实例停用 Voxy。不要删除正在使用的锁文件或数据库。

旧 `[红包助手] redpacket-1.0.0.jar` 是用户说明的失败品，本轮没有复用、删除或更改其配置。若检测到其 `enabled` 为 true 或配置损坏，新桥接停止自动动作，并写日志；手动输入不会受此冲突策略阻止。这个检测读取的是旧助手的配置文件，不代表已验证它所有运行时行为。

## 能力与限制

- 领取、聊天监控、手动指令、服务器原始点击动作及 TAB 在线名单通过游戏当前连接工作。
- 自动欢迎继续共用软件数据目录的每日 10 次总尝试限额，不因模式切换、重启或换服清零。
- 红包短期去重、限速和自然回执确认复用原逻辑；`suggest_command` 仅填软件输入框，不猜口令或自动提交。
- Mod 在真实服务器系统聊天包入口提取富文本及点击动作；玩家聊天与伪装玩家聊天只作显示，不登记可执行动作。不会靠 `latest.log` 猜指令，也不操作鼠标或键盘。
- 游戏断线、重新配置、换服或本地桥接断开使动作失效；请求 5 秒未获游戏回执即失败，不自动重发，不排队到下一会话。
- 游戏回执只证明发送方法在当前游戏主线程执行完成，不证明服务端接收、奖励到账，也不能保证其他 Mod 没有拦截或改写发送。到账仍以自然服务器回执为准。
- 本机传输的收发统计不是游戏连接的总网络流量；在线时间是软件开始观察当前桥接会话后的时间。
- 每日收购只读取主菜单导航和两类收购表的商店区域，不读取玩家背包；仅允许校验过的四个入口，不点击商品或鱼店。其他游戏界面会阻止自动采集；签到界面关闭后才继续。两类都完整保存后记为当天 1 次，售出量为采集时快照。
- 此版桥接未实现通用容器菜单镜像、任意背包操作、服务器命令补全或独立连接的原始协议诊断；每日收购的受限能力不开放任意容器点击。
- 连接模式会保存，但软件启动后不自动监听桥接或自动连接服务器。手动切模式仍需手动点连接；明确游戏下线且接管设置允许时，可自动切独立模式连接同一账号原服务器。
- 遵守目标服务器的自动化规则；本地配对令牌不能抵御能读取同一用户文件的恶意程序。
