# 芒果端辅助 V5.0 使用手册

适用：桌面端 5.0.0，桥接 Mod 1.2.0。日期：2026-10-21。

## 一、选择运行方式

- **独立连接**：不用启动 Minecraft，由软件以正版账号登录服务器。
- **游戏桥接**：游戏已经启动并进服，软件通过 Mod 复用游戏连接，查看聊天、发送命令及执行自动动作。

正在玩游戏时选择桥接，不要再用独立模式登录同一账号，以免互相挤下线。桥接不绕过正版认证，也不要求在软件账号栏再次登录。仅在服务器允许自动化时使用。

## 二、启动与账号

双击 V5.0 便携 EXE，不要同时运行多个版本。

独立连接步骤：选择“独立连接” → 点击“登录微软账号”（已有账号时可能显示“添加账号”） → 按提示在微软页面输入设备代码完成授权 → 添加或选择服务器并核对地址、端口 → 点击“连接”。

底部输入文字可聊天，以 `/` 开头则发送命令。“启动时自动登录账号”只是续期账号状态，不代表自动连接服务器。独立模式不模拟移动。

## 三、桥接需要哪些文件

当前配套文件：`mc-noclient-bridge-1.2.0+26.2.jar`。

项目内位置：`dist-3.0.1/mc-noclient-bridge-1.2.0+26.2.jar`。桌面升级到 V5.0 后仍使用此 Mod，不是寻找一个 5.0 的桥接 JAR。

已适配环境：Minecraft 26.2、Fabric Loader 0.19.3 或更高、Java 25，以及对应版本 Fabric API。不适用于其他 MC 版本、Forge 或 NeoForge。

1. 完全退出 Minecraft。
2. 在 PCL 等启动器中找到要玩的实例，打开该实例的实际游戏目录。
3. 将桥接 JAR 放入该实例的 `mods` 文件夹。
4. 已有旧桥接 JAR 时，将旧文件移出备份，不要同时安装两份同 ID 的桥接 Mod。
5. 继续按下一节导出配对。

启用版本隔离时，实例目录通常是 `.minecraft\versions\实例名称`；未隔离时可能直接是 `.minecraft`。以启动器为该实例打开的游戏目录为准。

## 四、如何导出配对（重点）

**只有 Mod 没有配对文件，桥接不会成功。**

1. 打开软件，在主界面连接面板选择“游戏桥接”。若有连接操作正在进行，先断开并等待完成。
2. 点击连接面板右侧的 **“导出配对”**。此按钮不在设置窗口里，独立模式下隐藏。
3. 保存窗口中，进入目标游戏实例的 `config` 文件夹；没有就先创建。
4. 保持文件名 **`mc-noclient-bridge.json`** 并保存。
5. 确认提示“配对文件已导出”，核对文件确实在目标实例中。
6. 如果游戏此前已经启动，完全退出并重新启动该实例，让 Mod 读取文件。

正确目录结构：

```text
实际游戏实例目录\
  mods\
    mc-noclient-bridge-1.2.0+26.2.jar
  config\
    mc-noclient-bridge.json
```

注意：

- 不要保存到 `mods`、启动器程序目录或另一个实例的 `config`。
- 文件不能叫 `mc-noclient-bridge.json.txt`，可开启资源管理器的文件扩展名显示检查。
- 使用“导出配对”按钮，不要直接复制软件的 `bridge-pairing.json` 后改名。
- 每个游戏实例都需要配对文件。同一台电脑、同一套软件数据可以使用同一份导出文件。
- 普通升级保留配对时不用重新导出。清空软件数据、换电脑或重新生成配对后，需要重新导出并更新游戏文件，再重启游戏。
- 配对文件含本地访问令牌，不能公开、上传、发群或贴完整内容排错。

## 五、启动和停止桥接

1. 确认 Mod 和配对文件安装正确。
2. 软件选择“游戏桥接”，点击“启动桥接”。
3. 通过启动器正常启动对应实例，正版登录并进入服务器。
4. 软件应从“等待游戏”变为“已进入游戏”，验证栏显示“游戏连接”。
5. 按需使用聊天、在线玩家和自动动作。

也可以先游戏进服，再启动桥接；Mod 会周期性重试本机连接。软件账号区未登录不影响桥接。

“断开桥接”只停止本地辅助通道，不替你退出游戏。游戏掉线、关闭后不能继续领取，旧动作不会排到下次连接补发。软件重启后需要手动启动桥接。

手动启动桥接可以持续等待游戏；独立模式被明确异地登录踢出后触发的自动转桥接，只检测同一账号已进服的本地游戏，检测窗口为 30 秒，超时停止。

## 六、自动欢迎和随机延迟

打开“设置 → 消息动作”：

1. 开启“自动点击欢迎（每日最多 10 次）”。
2. 开启“欢迎随机延迟”。
3. 填写最小、最大秒数，例如 `1` 和 `3`，每次随机等待 1 至 3 秒。
4. 点击“保存设置”。

默认范围 `0.40–0.85` 秒；允许 `0–30` 秒，最小值不能大于最大值。关闭随机延迟只是取消等待，不会关闭自动欢迎。

欢迎依赖服务器提供的欢迎入口，不会给普通进服消息编造欢迎命令。每日 10 次是同一软件数据目录共用的自动发送尝试额度，重启、换服、切换模式不清零。取消等待不计数，实际发送失败或结果不确定仍计一次。

断线、会话变化、暂停、修改相关设置或手动先点击会取消等待，过期动作不补发。

## 七、其他自动化

同样在“设置 → 消息动作”修改并保存：

- **自动红包**：开启“自动点击红包领取入口”，依赖服务器真实提供的动作，不猜口令或隐藏命令。
- **红包随机延迟**：按最小、最大秒数随机等待后尝试领取。
- **按领取人数触发**：观察到第 N 位不同玩家领取后尝试领取，不额外随机等待；十秒内人数不足则跳过。此模式与红包随机延迟互斥。
- **零点命令**：开启“每天本地 00:00:00 发送命令”，填一条以 `/` 开头的命令。到点须电脑未休眠、软件运行且已进服；错过不补发，失败不重试。
- **暂停全部自动化**：开启并保存后停止自动动作，手动发送不等同于自动化。

“已发送”或游戏回执不代表服务端执行成功、奖励到账，以服务器自然返回的确认消息为准。

## 八、聊天、日志、名单和记录

- “聊天”可按类别筛选，底部可手动发送消息和命令。
- “运行日志”可查看连接、账号、自动化和错误，未领取时先看“自动化动作”。
- “在线玩家”可筛选名单，为玩家开启或关闭发言监测。
- “加载更早聊天”按需读取历史；记录仅保留最近 7 天。
- 日志界面可选保留 200、400 或 800 条，这不是磁盘全部记录的总条数。
- “设置 → 记录与缓存”可以选择记录目录、打开目录、打开数据目录、生成脱敏诊断报告或重载界面。聊天、日志和缓存按最近 7 天保留。

上翻阅读时，新消息不会强制拉回底部，手动回到底部后恢复跟随。桥接仅监测实际出站命令，不会将箱子菜单槽位反推成隐藏命令，不提供容器菜单镜像或背包点击控制。1.2.0 不提供自动钓鱼控制。

2026-10-22 菜单点击改进版：独立连接可手动左键、右键点击服务器已经打开的箱子式菜单，例如公会金币签到；不需要知道按钮背后的隐藏命令。点击后等待服务端刷新，不自动重复；五秒无刷新则提示结果未知，需关闭再重新打开查看。背包、拖拽、Shift 转移和垃圾桶物品投放不在本次范围，游戏桥接不变。详见 `MENU_CLICK.md`。

## 九、常见问题

### 找不到导出配对

先切换“游戏桥接”，按钮在主界面连接面板右侧，不在设置中。按钮暂不可用时，等待当前连接操作结束。

### 一直等待游戏

1. 检查启动的是否就是放入 JAR 和 JSON 的实例。
2. 检查 JAR 在 `mods`，JSON 在 `config`，文件名没有多余扩展名。
3. 导出或换配对后，完全重启游戏。
4. 检查 MC、Fabric、Java、Fabric API 是否符合要求，桥接 Mod 是否加载成功。
5. 游戏需真正进入服务器，而非停在主菜单。
6. 确认软件点了“启动桥接”，没有同时运行另一份程序。
7. 清空软件数据后，重新导出配对，不要继续使用旧文件。

桥接只用本机通道，不需开放路由器端口。不要为排错关闭整个防火墙或发出令牌。

### 在线但没有自动动作

检查暂停开关、对应功能开关、是否保存设置、欢迎额度、服务器是否提供动作入口。查看自动化及错误日志。如果提示旧红包助手冲突，检查相关 Mod 配置，避免两套自动化同时操作。

### 无数据版仍显示自己的数据

无数据版不内置个人数据，但会读取本机已有数据。两个版本共用用户目录，换文件夹无效。恢复默认前需从托盘彻底退出所有版本，再备份清理，不能运行中直接删数据。

清理后先开含数据版可能重新导入私人快照，保持默认状态应使用无数据版。自定义记录目录和游戏实例内的配对文件位于其他位置，不能假定清理默认应用目录就一并删除了。

### 关闭窗口后程序还在

检查“设置 → 账号 → 关闭窗口时”。选“后台运行（托盘）”时关窗口只是隐藏，要在托盘选择“退出”才完全结束。

## 十、隐私与排错

可以提供版本号、连接模式、错误时间、相关错误片段和脱敏诊断报告。不要提供 `accounts.json`、完整配对文件、令牌、设备授权码、含数据版 EXE 或未经检查的完整数据目录。

本手册依据 V5.0 源码和已有离线验证整理，具体整合包和服务器兼容性以实际加载及服务器回执为准。
